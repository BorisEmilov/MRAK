# Quests

Status: Draft v0.1 · MVP: ✅ · Package: `packages/core/quests` · Back to [GDD](../GDD.md) · [index](README.md)

## Purpose

Track goals: chapter objectives, villager arcs, night objectives, route milestones. Mysteries are a
special quest type with their own board ([mysteries](mysteries.md)).

## Data

Content `quests/*.json`: `{ id, kind (chapter|villager|night|route|endless), stages: [{ id, objectives:
[{ condition, optional }], onComplete: effects[] }], failConditions[], deadline? }`.
State: `{ questId, stageId, objectivesDone[], status (active|done|failed|abandoned) }`.

## Rules

1. Conditions are declarative (event + predicate), evaluated by core on events.
2. Quests can **fail** permanently (deadline, death) — failure is a story branch, not a reload prompt.
3. Night objectives: 1–2 per night, generated by the director from the chapter pool.
4. Villager arcs continue across chapters; some cross generations (the villager's child).
5. Completing a stage may award Revelation via milestone IDs, never directly.

## Initial formulas

- Night objective pool weights: chapter-specific; a failed night objective does not return the same night.

## Events

- **Emits:** `quest/started`, `quest/stageAdvanced`, `quest/completed`, `quest/failed`.
- **Consumes:** any domain event (via condition evaluation).

## Edge cases

- A quest's villager dies → `failConditions` or alternative stage defined in content.
- Content update changes stages → migration maps old stage IDs.

## Test ideas

- Condition engine: event matching with predicates on payload.
- Deadline at night 12 fails the quest at dawn of night 12 exactly.
- Death of a required villager triggers the content-defined fallback.

## Implementation (v1)

- **Data:** `quests/*.json` adds `icon`, `excludes: quest[]` (rival routes), objective `marker
{ zone, poi }` (map marker) and stage `noReturn: true` (point of no return).
- **Engine (core):** after every command and tick, active quests are evaluated: when every
  non-optional objective of the current stage holds, `onComplete` applies and the next stage
  starts (`quest/stageAdvanced`) or the quest ends (`quest/completed`); `failWhen` fails it
  (`quest/failed`).
- **Exclusion:** a quest cannot start while a quest it excludes (or that excludes it) is active or
  done — `startQuest` is refused with `quest/blocked`. Completing a quest fails the active quests
  it excludes (`quest/failed { by }`). Exclusion is symmetric.
- **Point of no return:** entering a `noReturn` stage emits `quest/noReturn`; the UI shows only a
  subtle sign — a candle going out — never a warning text.
- **UI:** the journal's Quests tab (icon, current stage, objectives ticked, failed and done ones),
  and markers on the map for objectives with a `marker` in the current zone.
